# SQL智能纠错系统 - 完整流程与数据处理走向文档

## 一、系统概述

### 1.1 系统定位
SQL智能纠错系统是一个基于AI（Ollama本地大模型）的SQL代码审查工具，用于对比SQL存储过程与IT-Mapping文档的一致性，自动发现字段映射、表间关联、转换逻辑等方面的问题。

```

│  ┌─────────────────────────────────────────────────────────────────────┐   │
│  │                      并行执行3个FieldCheckAgent                       │   │
│  │                                                                      │   │
│  │   Agent 1                    Agent 2                    Agent 3     │   │
│  │      │                          │                          │        │   │
│  │      ▼                          ▼                          ▼        │   │
│  │   调用Ollama                调用Ollama                调用Ollama    │   │
│  │   API分析                   API分析                   API分析       │   │
│  │      │                          │                          │        │   │
│  │      ▼                          ▼                          ▼        │   │
│  │   返回结果:                 返回结果:                 返回结果:     │   │
│  │   {status, issue,           {status, issue,           {status,     │   │
│  │    explanation,              explanation,              issue, ...} │   │
│  │    suggestion, ...}          suggestion, ...}                      │   │
│  └─────────────────────────────────────────────────────────────────────┘   │
│                              │                                              │
│                              ▼                                              │
│  ┌─────────────────────────────────────────────────────────────────────┐   │
│  │                         投票决策逻辑                                  │   │
│  │                                                                      │   │
│  │   统计状态:                                                          │   │
│  │   • consistent_count: 认为一致的Agent数                              │   │
│  │   • inconsistent_count: 认为不一致的Agent数                          │   │
│  │   • warning_count: 警告数                                            │   │
│  │   • error_count: 错误数                                              │   │
│  │                                                                      │   │
│  │   决策规则 (consensus_threshold=2):                                  │   │
│  │   • consistent_count >= 2 → 最终状态: consistent                    │   │
│  │   • inconsistent_count >= 2 → 最终状态: inconsistent                │   │
│  │   • 其他情况 → 最终状态: needs_review                                │   │
│  └─────────────────────────────────────────────────────────────────────┘   │
│                              │                                              │
│                              ▼                                              │
│  ┌─────────────────────────────────────────────────────────────────────┐   │
│  │                         计算置信度                                    │   │
│  │                                                                      │   │
│  │   置信度 = max_count / valid_total                                   │   │
│  │                                                                      │   │
│  │   示例:                                                              │   │
│  │   • 3:0 一致 → 置信度 1.0                                            │   │
│  │   • 2:1 一致 → 置信度 0.67                                           │   │
│  │   • 1:1:1 分歧 → 置信度 0.33                                         │   │
│  └─────────────────────────────────────────────────────────────────────┘   │
│                                                                              │
│  输出: { field, final_status, vote_details, confidence, merged_findings }  │
│                                                                              │
└─────────────────────────────────────────────────────────────────────────────┘
```

## 十二、重试机制

### 12.1 指数退避策略

```
重试延迟计算公式:
delay = base_delay * (exponential_base ** retry_count)

默认参数:
- max_retries: 3
- base_delay: 1.0秒
- max_delay: 60秒
- exponential_base: 2.0

示例:
第1次重试: 1.0秒后
第2次重试: 2.0秒后
第3次重试: 4.0秒后
```

- IOError
- OSError

- 其他网络相关异常

## 十三、总结

SQL智能纠错系统通过以下核心流程实现SQL与IT-Mapping的自动对比审查：

1. **文件解析阶段**: 解析IT-Mapping Excel提取字段映射规则，解析SQL提取字段取值表达式
2. **AI分析阶段**: 使用三Agent投票机制，对每个字段进行并行检查并投票决策
3. **结果存储阶段**: 将检查结果存储到SQLite数据库，支持历史查询和报告生成
4. **结果展示阶段**: 前端展示检查结果，支持筛选、搜索和导出

系统的核心优势在于：
- **多Agent投票机制**: 提高判断准确性，减少误报
- **并行处理**: 支持多字段并行检查，提高效率
- **可扩展架构**: 易于添加新的检查维度和SQL方言支持
- **完整的数据追踪**: 所有检查结果存储在数据库中，支持历史回溯
- **数据流管道**: DataFlowManager提供完整的端到端数据处理能力
- **Harness架构**: 支持灵活的字段提取和对比流程
- **重试机制**: 指数退避策略确保系统稳定性
